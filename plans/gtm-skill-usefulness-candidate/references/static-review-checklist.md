# Increment 1 static review checklist

[Book index](../book/index.md) · Foundation review, **not** runtime certification

- [ ] `SKILL.md` has valid `name` / `description` YAML frontmatter, narrow GTM triggering and clear foundation-only status.
- [ ] No Goal Memory or `memory temp/` dependency is introduced.
- [ ] Lightweight and full research are distinguished by actual complexity and evidence needs.
- [ ] Explicit charter, plan, scope, spending and installation gates are stated.
- [ ] Workspace root must be approved before live initialization; no workspace is created as a side effect of skill packaging.
- [ ] Workspace-wide concept ID vs project-scoped research ID vs `DR-###` decision-label namespaces are distinct.
- [ ] Issued IDs are never reused, including following interrupted writes.
- [ ] Approval records cannot be fabricated; workflow requires durable decision evidence.
- [ ] Ordered writes put substantive records before indexes and the active checkpoint.
- [ ] Recovery and single-writer limitations are documented; inconsistent state blocks writes.
- [ ] Book/index and all Part indexes resolve and enumerate Chapters 01–14.
- [ ] No links to as-yet-unmaterialized chapter files are presented as working links.
- [ ] DR-001–DR-052 each appear once in the primary coverage map.
- [ ] R-01–R-08 have reviewable safeguards, including the standalone amendment.
- [ ] Foundation does not falsely assert that evidence, red-team, budget or release workflows are fully implemented.
- [ ] No script, paid service call, live installation or research project is created.

A static pass does not demonstrate that the skill will reliably execute every workflow in a real Codex environment. Full operational review and release approval remain future gates.
