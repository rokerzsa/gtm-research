# Increment 6 — Final Static Review Checklist

[Final audit procedure](final-static-audit.md) · [Specification book](../book/index.md) · [Current review record](../book/appendices/increment-6-review.md)

**Check scope:** Instruction, link, template, and package consistency only. These items are for static inspection, **not** for simulation of actual Codex actions, a website build, or permission to release.

- [ ] Current `SKILL.md` frontmatter and all six-increment capabilities are described without claiming installation or runtime proof.
- [ ] All fourteen full normative chapters exist and appear in logical order in main and part indexes.
- [ ] DR-001–DR-052 each have exactly one primary chapter mapping; revised DR-040/041/042/044 entries are counted once.
- [ ] R-01–R-08 and the standalone/no-Goal-Memory amendment remain intact.
- [ ] Historical Increment 1–5 review records are unchanged; current instructions do not retain stale previous-release stop conditions.
- [ ] Approved charter, high-level plan, detailed plan and contract boundaries remain distinct.
- [ ] Inspected evidence is differentiated from discovered/secondhand sources; confidence, evidence, review, execution, lifecycle remain distinct.
- [ ] Independent `RT` investigation covers major and aggregate conclusions, with bounded adjudication and unresolved material dispute handling.
- [ ] Multidimensional budget usage/ceiling measurement and preauthorized extensions remain correctly bounded.
- [ ] Subphase completion dossier checks every contract criterion, mandatory `RT`, gaps, dependencies and outputs before checkpoint completion.
- [ ] Project completion dossier checks the **approved charter** and reader-facing book, not just a task list.
- [ ] Consequential cross-project dependencies and reopened completed work preserve prior dossiers and authorization limits.
- [ ] Recovery enforces single-writer, no ID reuse, no fabricated approval and checkpoint-last ordering.
- [ ] All internal Markdown file links resolve and stable identifier namespace examples do not collide.
- [ ] New templates are empty/illustrative with no invented sources, customers or approval claims.
- [ ] No external skill, Goal Memory service, mandatory Docusaurus build, live workspace initialization, paid research or release is implied.
- [ ] Static report distinguishes checks passed from **not verifiable statically** and enumerates package files/differences/hash.

A pass on these checks makes the ZIP **reviewable**, not approved for installation or guaranteed to run correctly.
