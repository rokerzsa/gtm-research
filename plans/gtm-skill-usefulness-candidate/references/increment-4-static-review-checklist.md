# Increment 4 — Static Review Checklist

[Book index](../book/index.md) · [Chapter 05](../book/part-02-investigation/05-independent-red-team-review.md) · [Chapter 06](../book/part-02-investigation/06-research-budgets.md)

**Method:** Static inspection of package files, instructions, templates, link integrity and source-tree/ZIP manifests. No company research, independent *runtime* red-team execution, budget spending, live workspace initialization or Codex installation is implied. Distinguish observed static facts from behavioral guarantees.

- [ ] `SKILL.md` has valid frontmatter and accurately defines Increment 4 available and future capabilities.
- [ ] Standalone OKF conventions and Increment 1–3 charter, plan, source, claim, gap and journal features are preserved.
- [ ] Major-conclusion classification considers goal, causal, strategic, dependency, uncertainty and aggregate-conclusion significance.
- [ ] An aggregate causal conclusion cannot bypass review by splitting constituent claims.
- [ ] Red-team pass is a **separate evidence-seeking adversarial investigation**, not a proofread/self-critique; separate model optional.
- [ ] Review `RT` record freezes exact initial target and cites original sources and independently sought counterevidence, alternative mechanisms, falsifiers and negative searches.
- [ ] Review `RT` identity is durably allocated from the existing project `record-ids.md`; no new global allocator.
- [ ] Genuine adversarial investigation and bounded adjudication are prerequisites to `passed` / `qualified`; material unresolved disputes retain `unresolved` and escalate.
- [ ] Evidence state, qualitative confidence, independent review state, lifecycle state and execution remain distinct.
- [ ] A completed red-team review does not automatically increase confidence, prove a historical proposition or close a subphase.
- [ ] Adaptive budgets support assigned source investigations, research passes, exploration, time, money, tokens and optional dimensions.
- [ ] Budget usage is `measured` / `estimated` / `unavailable` with basis, never invented or falsely zeroed.
- [ ] Initial base, explicitly preauthorized extension and total hard ceiling are distinct and tied to actual approval IDs.
- [ ] Extension use requires documented expected information gain, dimension and quantity before expenditure.
- [ ] An authorization to consume a preapproved extension is **not** an authorization to increase the ceiling.
- [ ] Project/phase/subphase ceilings and mixed dimensions are checked; child capacity does not bypass parent and usage is not double counted.
- [ ] No unapproved paid access or risk of exceeding an unenforceable hard ceiling is permitted, including token usage.
- [ ] Budget exhaustion is never evidence exhaustion or a research completion criterion.
- [ ] Budget and review records link to existing `DEC`, `SRC`, `CLM`, concept and journal identities.
- [ ] Stable IDs, substantive writes and budget/review records precede dependent indexes/journal references and the checkpoint update.
- [ ] Interruptions preserve allocated IDs, durable event history and honest recovery limitations.
- [ ] Chapters 05–06 are full, navigable and linked from Part II, book home and `SKILL.md`.
- [ ] Previous Increment 1–3 review records remain unmodified as historical snapshots.
- [ ] Increment 5–6 capabilities remain explicitly unavailable; no live workspace/research or installation implied.
- [ ] Primary DR-001–DR-052 coverage has 52 unique assigned decisions including standalone `-R` revisions and R-01–R-08 safeguards remain intact.
- [ ] All local Markdown file links resolve (ignore template placeholders where explicitly marked).
- [ ] ZIP file list matches source tree, has valid CRC, and contains a single self-contained skill root.

A successful static review does **not** demonstrate independent research judgment, budget enforcement, or runtime Codex integration in actual execution. Every future increment requires explicit separate approval.
