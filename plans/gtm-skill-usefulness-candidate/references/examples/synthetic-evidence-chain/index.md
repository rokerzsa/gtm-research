# Synthetic OKF Evidence Chain — Worked Example

> **FICTIONAL DOCUMENTATION EXAMPLE ONLY.** All organizations, events, source descriptions and dates below are invented to demonstrate record linking. No external website was accessed, no real paid customer is asserted, no `K`/`PRJ` ID was actually allocated in a live workspace, and no research project was completed.

This miniature **post-split** example uses two registry files so a researcher can verify a real Markdown link path through the whole reader-facing chain.

1. [Chapter-style reader narrative](book-chapter.md): the claimed observation and limitation.
2. [Reusable `K-000001` concept](concept.md): supports a semantically reusable finding.
3. [Claim `PRJ-0001:CLM-0001` and red-team `PRJ-0001:RT-0001`](claims-and-reviews.md): evidence state, counterevidence and review distinction.
4. [Source `PRJ-0001:SRC-0001`](sources.md): fictional provenance record and access limitations.

## Demonstrating link repair after a registry split

Imagine the fictional source record **previously** occupied an anchor `#src-0001` in a combined `claims-and-reviews.md` registry. After splitting sources into `sources.md`, the stable qualified ID remains `PRJ-0001:SRC-0001`, while the correct **current** link becomes [source `PRJ-0001:SRC-0001`](sources.md#src-0001). The [claim](claims-and-reviews.md#clm-0001), [concept](concept.md), and [book chapter](book-chapter.md) use the new link. The previous location is retained here only as a description, not as an authored broken link. In real work, preserve a relocation/supersession history and repair indexes/checkpoint after validating targets.

## What this example proves—and does not

It demonstrates **static link resolution and record semantics**: book → concept → claim/review → source. It does not prove that Codex will conduct independent red-team investigation, manage hard budgets, or recover from crashes in a live workspace. For an actual research task, allocate IDs durably and use real inspected sources under an approved contract.
